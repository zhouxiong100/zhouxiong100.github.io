## 先给结论

AI Agent 能不能干活，取决于模型、工具和协作机制是否连得起来。
这三种协议分别回答三个不同的问题：

| 协议 | 核心问题 | 典型关系 | 适合场景 |
| --- | --- | --- | --- |
| **MCP** | Agent 如何安全、统一地使用工具和数据？ | Agent/客户端 ↔ 服务端 | 查询数据库、读文件、调用内部 API |
| **ACP** | 本地或边缘 Agent 如何轻量地交换消息？ | Agent ↔ Agent | 机器人协同、设备联动、弱网环境 |
| **A2A** | 不同平台的 Agent 如何发现彼此并共同完成任务？ | Agent ↔ Agent | 跨团队、跨厂商、跨云的任务协作 |

可以把三者放在一张关系图里理解：

```text
业务 Agent ── MCP ──> 工具、数据库、文件、内部 API
     │
     ├── A2A ──> 其他平台或组织的 Agent
     │
     └── ACP ──> 同一本地网络中的 Agent、设备
```

它们不是互相替代。**MCP 解决“对内连接”，ACP 解决“本地通信”，A2A 解决“对外协作”。**

## MCP：Agent 与工具之间的标准接口

MCP（Model Context Protocol）解决的是最常见的工程问题：
每接一个客户端，就要为每个工具重复写一套适配。

MCP 把连接拆成两部分：客户端支持 MCP，工具侧提供 MCP Server。
这样，新的客户端不必重新适配每个工具，新的工具也不必逐个适配所有客户端。

一次调用通常很直接：

1. 客户端发现 Server 提供的 Tools、Resources 或 Prompts。
2. 模型选择工具并提交结构化参数。
3. Server 做权限校验，调用真实系统。
4. Server 返回经过裁剪、适合放入上下文的结果。

例如，客服 Agent 需要查订单时，模型只提交订单号；
数据库连接、字段筛选和权限凭证留在 MCP Server 一侧。
这让凭证不直接进入模型上下文，也让多个 Agent 可以复用同一套访问规则。

已有文章详细介绍过 MCP 的 N×M 问题，可继续阅读
[《MCP 到底解决了什么问题》](/posts/2026/10/mcp-explained/)。

## ACP：面向本地 Agent 的轻量通信

本文中的 ACP 指 BeeAI 与 IBM 推动的
[Agent Communication Protocol](https://agentcommunicationprotocol.dev/)，
重点是 Agent 之间的直接消息交换，而不是 Agent 调用数据库或文件。

它更关注这些约束：

- **低延迟**：交互发生在同一台机器或同一局部网络内。
- **轻量连接**：适合本地进程、边缘设备和资源受限环境。
- **弱网可用**：网络不稳定时，本地节点仍能继续工作。
- **能力发现**：节点可以说明自己支持什么操作、接收什么消息。

典型流程是本地 Agent 宣告能力，另一个 Agent 建立会话并发送结构化请求，
双方交换消息、状态和结果。它更像一张“内部电话线”，适合持续的点对点通信。

{: .note }
ACP 是容易混淆的缩写。Google 还有一个面向模型与本地工具客户端的
Agent Client Protocol；讨论协议时，最好直接写出全称和项目链接。

## A2A：跨平台 Agent 的任务协作

A2A（Agent-to-Agent）面向更大的边界：
两个 Agent 可能来自不同团队、不同厂商，使用不同模型和运行时，
彼此也没有共享内部代码。

它重点解决的不是一次函数调用，而是一次完整协作：

1. **发现**：读取对方的 Agent Card，了解身份、能力、端点和权限要求。
2. **协商**：确认任务目标、输入、输出、进度与失败条件。
3. **执行**：发送任务，接收流式反馈、中间结果或状态变化。
4. **闭环**：提交最终结果，处理取消、重试、评价和审计。

比如，你的客服 Agent 通过 MCP 查询自己的订单系统，
再通过 A2A 把“确认发货时间”交给物流伙伴的 Agent。
两边不需要暴露内部数据库，也不需要共享同一套框架。

## 怎么选？

用三个问题判断：

- **我要调用工具或读取数据吗？** 优先看 MCP。
- **通信双方都在本地，并且要轻量、低延迟吗？** 看 ACP。
- **要跨平台发现 Agent、协商任务并交付结果吗？** 看 A2A。

一个真实流程可以同时用到它们：

```text
客服 Agent --MCP--> 订单系统
客服 Agent --A2A--> 物流 Agent
仓库 Agent --ACP--> 分拣设备 / 本地机器人
```

{: .pitfall }
协议选型不能只看名称。先确认对端实际支持什么版本、传输方式和安全机制，
再设计连接；“支持某个协议”不等于双方默认可以互操作。

## 一句话回顾

**MCP 让 Agent 用上外部能力，ACP 让附近的 Agent 直接说话，**
**A2A 让不同平台的 Agent 一起完成任务。**

三种协议解决的是不同层的问题，真正落地时通常按边界组合使用，
而不是把它们当成三个互相竞争的选项。
